# Allianz — dbt / Snowflake Data Vault take-home

Runnable demonstration of an insurance Customer–Policy Data Vault, including 2 hubs, 1 link, 2 historized satellites, a Business Vault current-state view, source definitions, tests, and dbt documentation.

## Prerequisites
Python 3.10–3.13 recommended, a Snowflake account, privileges to create database/schema/warehouse, and Git.

## 1. Snowflake setup
Execute `setup/01_setup.sql` in a Snowflake worksheet with an administrative role.

## 2. Install and configure
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdir -p ~/.dbt
cp profiles.example.yml ~/.dbt/profiles.yml
export SNOWFLAKE_ACCOUNT='your_account_locator'
export SNOWFLAKE_USER='your_username'
export SNOWFLAKE_PASSWORD='your_password'
export SNOWFLAKE_ROLE='ACCOUNTADMIN'
dbt debug
```
If you use SSO/MFA instead of a password, adjust the profile authentication method. Never commit secrets.

## 3. Run all four batches
```bash
./scripts/run_demo.sh
```
This loads seed tables into RAW, builds staging views, vault tables and tests sequentially for batch 1 through 4, and generates documentation. Results are captured in `evidence/batch_*.log`.

For a single run:
```bash
dbt seed --full-refresh
dbt build --vars '{batch_num: 1}'
dbt test --vars '{batch_num: 1}'
dbt docs generate
dbt docs serve
```

## 4. Verify results in Snowflake
```sql
select count(*) from ALLIANZ_DEMO.RAW_VAULT.HUB_CUSTOMER; -- expected 3 after batch 4
select count(*) from ALLIANZ_DEMO.RAW_VAULT.HUB_POLICY; -- expected 3
select count(*) from ALLIANZ_DEMO.RAW_VAULT.LINK_CUSTOMER_POLICY; -- expected 3
select count(*) from ALLIANZ_DEMO.RAW_VAULT.SAT_CUSTOMER; -- expected 5
select count(*) from ALLIANZ_DEMO.RAW_VAULT.SAT_POLICY; -- expected 4
select customer_id, customer_name, city, effective_at, load_datetime
from ALLIANZ_DEMO.BUSINESS_VAULT.BV_CUSTOMER_CURRENT order by customer_id;
```
Expected counts apply to a clean sequential demo. Run 4 includes an event with an earlier business-effective date but later load date.

## 5. Repeatability and reset
For a clean restart, drop the five RAW_VAULT models (or the RAW_VAULT schema, then recreate it using setup SQL), and rerun `./scripts/run_demo.sh`. Do not use `dbt run --full-refresh` on the entire project when trying to preserve history.

## Artifacts and discussion
- `docs/architecture.md` documents key design decisions and limitations.
- `docs/development_guidelines.md` covers standards and team maturity.
- `docs/test_results_template.md` is a fill-in test report; actual logs are created only when you execute the project.
- `target/manifest.json`, `target/run_results.json`, `target/catalog.json` are generated by dbt, not shipped as fabricated outputs.

## Evaluation mapping
Data Vault: `models/raw_vault`; transformations: `models/staging`; tests: `models/**/*.yml` and `tests/`; docs: this README and `docs/`; logging: `scripts/run_demo.sh` and generated evidence.
